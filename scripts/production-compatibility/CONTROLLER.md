# Proposed local PG18 controller

The controller is source only and has not been imported, parsed, syntax-checked or executed. It creates no user unit, timer or runtime resource during authoring. Root must apply it to the admitted API tooling lane, commit before validation, syntax-check the committed candidate and obtain independent source and exact finite operation review before Docker. It sits beside the production reader and outside qualification/, so the reader's 20-file closure and qualification's exact six-file closure remain unchanged. The new tooling commit/tree and controller hash bind this additional source separately.

The default invocation prints an unbound plan without reading an operation request, contacting Docker or creating a directory. Execution requires /usr/bin/python3 -I, the committed fixed controller path, --request followed by an absolute request path, --review followed by its independently accepted review path, and --execute. No alternate repository, image, driver, database URL, Docker endpoint or resource values can be selected by CLI. The Docker endpoint is fixed to unix:///var/run/docker.sock. Root must verify that this is the cached local daemon used by the native probe; an unavailable endpoint refuses without fallback.

## Parent request and independent review

Root supplies a fresh local-pg18-compatibility-controller-request-v1 object. Its fields are tooling_source, tooling_tree, controller_sha256, driver_sha256, manifests, binaries, run_root, unit_name, starts_at and expires_at. tooling_source/tree identify the final committed controller-plus-driver candidate. manifests has release, reader and qualification SHA-256 values for the three fixed source manifests. binaries has exactly python, docker, git, timeout, bun, node and systemctl hashes for the fixed absolute paths in the source. No password or managed credential belongs in this object.

run_root is /tmp/pirate-v1-compatibility- followed by a fresh 32-hexadecimal suffix. It must not exist. unit_name is pirate-v1-compatibility- followed by that suffix and .service. UTC timestamps must end in Z. The total window is at most 360 seconds, must have started, and must have at least 330 seconds remaining before any resources. At least 240 seconds must remain when the derived admission is prepared and 255 seconds after the final source recheck before launching Bun, allowing the driver's own source bootstrap to enforce its existing 240-second minimum. Fresh checks immediately before Docker create and start require at least 330 seconds remaining, reserving the container's 300-second TERM deadline, ten-second escalation and twenty-second cleanup margin within the reviewed UTC window. A slow source check or creation refuses and cleans an already owned created CID normally rather than extending the window.

The independent-local-pg18-compatibility-operation-review-v1 object contains request_sha256, controller_sha256, actual UTC reviewed_at, accepted true, reviewer_role independent_reviewer, empty findings, and authorizes_derived_local_admission true. This is the genuine separate review of the exact request and conditional derivation, not a controller-created review. Request and review bytes are read once and hashed, then rechecked before resources, admission, completion and final custody checks.

After actual CID, image, labels, network, mounts, resource limits, socket and cgroup observations pass, the controller copies the genuine acceptance/role/findings into admission.json required by the existing driver. It includes parent request/review hashes and explicitly labels the observed runtime facts as not an independent attestation. It never invents a reviewer, result or production acceptance. No operation request, accepted review, derived admission, PID, CID or runtime result is supplied by this proposal.

## Finite process and container bounds

Root creates the single separately reviewed user unit. The controller does not start one. The unit must have MemoryMax 512 MiB, MemorySwapMax zero, CPUQuota 25 percent, CPUAffinity 1, TasksMax 128, RuntimeMaxSec 360 and TimeoutStopSec 20. AllowedCPUs is not used. Before resources and after cleanup the controller verifies its actual cgroup memory/swap/CPU/PID limits, /proc CPU affinity, exact unit cgroup and systemd deadlines. The supported systemctl deadline strings are 6min or 360s, and 20s. Unknown representations fail closed and need reviewed source qualification rather than an inferred waiver.

The sole container uses cached image sha256:4ef4dbc939d61acea57712655ddb4b4ab27419c913f94cca0cd57cb3ea3c2280, pull never, network none, no public ports, restart no, one CPU quota on CPU2, memory 1536 MiB with equal total memory-plus-swap, 128 PIDs and 64 MiB shared memory. PGDATA remains /var/lib/postgresql/18/docker. The image's /var/lib/postgresql volume is overridden by a 512 MiB tmpfs; /tmp is a 64 MiB tmpfs. Any anonymous volume or unexpected bind mount refuses. Only the owned socket directory is mounted read/write at /var/run/postgresql. No source or credential directory is mounted.

The parent run directory is mode 0700. The socket directory starts at mode 3775. The image's entrypoint chown may clear its setgid bit, producing the observed mode 1775, and may change its owner to the PostgreSQL UID. Both exact modes are accepted only inside the source-created non-symlink mode-0700 parent owned by the current host user; both directory mode/UID/GID observations are preserved before validation. Host access depends on the socket/directory modes within the private parent; the controller does not falsely require the socket UID to remain the host user. It verifies the actual Unix socket after the image reports completed initialization and pg_isready succeeds, avoiding its temporary initialization server.

The exact container command has GNU timeout TERM at 300 seconds and KILL ten seconds later, then the official entrypoint with listen_addresses empty, max_locks_per_transaction 64, shared_buffers 64MB, the fixed socket directory and unique cluster_name. Docker inspect is parsed only in memory. Saved evidence contains only filtered identity, owned labels, limits, state, actual cgroup values and known process identities. Env, raw inspect and image author metadata are never saved. Actual in-container memory.swap.max must be zero, CPU quota one, effective CPU2 and pids.max 128.

The host driver runs under the fixed GNU timeout with TERM at 240 seconds and KILL ten seconds later. It uses the already committed Bun driver, local dependencies and owned Unix socket. The controller generates a fresh synthetic 64-hexadecimal password only in memory and child environment; neither argument lists nor saved requests contain it. Ambient database/provider/authentication variables are forbidden, and child environments use a small allowlist. Child Git observations set GIT_OPTIONAL_LOCKS=0 so retained application index metadata is not refreshed. The only container password variable and driver password variable are synthetic. Docker uses a new empty private configuration directory, not the user's credential configuration.

## Results and normal cleanup

The controller preserves the new run directory, genuine driver result and exact safe stdout/stderr hashes or logs. Driver and Docker log text is redacted in memory for the exact synthetic password before writing. Qualification success requires actual zero driver exit, genuine success, 19 cases, 14 complete queries and acknowledged connection close. It does not substitute a proposed case list for execution evidence.

Driver failure, deadline or signal does not bypass container cleanup. An ambiguous create acknowledgement may be resolved only through the derived exact name and matching actual CID/image/request/review labels. Ownership checks are separate from resource acceptance, so a refused resource guard does not prevent normal cleanup of an exact owned container. A failed best-effort process census during cleanup likewise does not prevent its stop. The controller normally stops that exact owned CID, verifies stopped state, captures filtered state and redacted logs, and removes only that stopped CID. There is no pull, force removal, global prune or foreign-container cleanup. Known PID instance identities and the socket/lock must be absent afterward. Abnormal/OOM/deadline/forced exit still marks failure even if the stopped owned container can be removed safely. Acceptable normal container exit statuses are zero, 130 and 143; an unexpected actual status requires preserved review, not silent acceptance.

If identity or cleanup cannot be proved, the result remains failed and preserves the observed failure rather than claiming resources disappeared. Final absence requires a successful daemon response to an exact CID-filtered list, not merely a failing inspect command. A hard user-unit kill may prevent its final result from being published; an absent, empty or partial result is failure evidence. The root must inspect the exact owned resources under existing custody before any successor. The container's independent hard timeout remains a second bound, not evidence that cleanup succeeded.

Source, application, manifest, binary and parent review hashes are rechecked after the driver and cleanup. The actual production operation namespace must remain absent throughout these checks. Nothing here accesses production, staging, a phone, wallet, profile, provider or managed credential. The controller qualifies only the existing driver's declared local SQL matrix and preserves its remaining unproved cases. No actual resource slot or operation is authorized by this source proposal.

## Parallel local fixtures

Other independently owned containers do not block this fixture merely by existing. The controller records their IDs as foreign observations and never sends them mutation commands. Its own request-derived name, private run/socket directory, network-none mode, no ports, tmpfs and exact ownership labels separate its state from theirs. Before creation and again before start, actual host MemAvailable must be at least four GiB; our existing controller and container caps total two GiB with zero swap. Active HNS quiet windows still exclude this job. Shared host/daemon contention and later memory changes remain real limits: headroom is a point-in-time observation, and actual OOM/deadline/cleanup failures still fail. This changes no production, foreign resource or host quiet-window authority.
