# Service-only protocol version 1

These preimages belong to the standalone ceremony service. They are not wrapper permits, accepted registry ABI or authority grants. test/vectors/ceremony-v1.json publishes literal inputs and expected digests; test/vectors.test.ts checks them. Changing these bytes requires a new protocol version and review before live publication.

Addresses and hashes are lowercase 0x hex, network is main or regtest, TLD is canonical lowercase ASCII, and timestamps are bounded Unix seconds. namespaceId is keccak256(abi.encode(keccak256(bytes("pirate.namespace/1")), keccak256(bytes(tld)))). Binding digest is keccak256 of the ordinary ABI tuple in this order: domain hash of pirate.namespace-ceremony-binding/1, network string hash, namespaceId, chainId:uint256, registry:address, wrapper:address, controller:address, grantSigner:address, installationKey:address, communityId:bytes32, installationId:bytes32, revision:uint64, hostingOrigin string hash, sourceSha256:bytes32, deploymentDigest:bytes32. ABI encoding is not packed. Hosting origin is context and proves no namespace authority.

The publication challenge is SHA256 of the ordinary ABI tuple domain hash of pirate.hns-publication-challenge/1, ceremonyId:bytes32, bindingDigest:bytes32, nonce:bytes32, publicationDeadline:uint64 and maturitySeconds:uint64. The lifetime is 172800 seconds and maturity duration 86400 seconds. pc1 is pc1: followed by unpadded canonical base64url of that 32-byte hash.

Persistent pd1 is pd1: followed by unpadded canonical base64url of chainId:u32be, registry:20bytes, controller:20bytes and communityId:32bytes. Its text length is 106. pc1 text length is 47. Two separate TXT records contribute 159 bytes, excluding the resource's shared version byte and any added routing record. Preflight always serializes the complete final resource and preserves its existing records. _evm routing format and interpretation remain the frozen resolver grammar recorded in PROVENANCE.md.

Controller consent uses EIP712 domain name PirateNamespaceCeremony, version 1, bound chainId and verifyingContract=wrapper. Primary type CeremonyConsent contains ceremonyId, bindingDigest, resourceDigest and nonce as bytes32, then issuedAt and deadline as uint64. resourceDigest is SHA256 of the exact complete planned resource wire bytes. The nonce is random 32-byte entropy, not an account identity. A bad signature never consumes the challenge. The controller can renew expired consent; maturity is re-observed before later effects.

HTTP access has a separate EIP712 domain PirateNamespaceHttp/version 1, same chain/wrapper. Primary type ApiRequest contains bindingDigest:bytes32, method:string, path:string, bodyDigest:bytes32, nonce:bytes32, issuedAt:uint64 and deadline:uint64. bodyDigest is SHA256 of exact UTF8 request body bytes; reads use an empty body. Path is the exact pathname; query strings are refused. Uppercase HTTP methods match Request.method. Required headers are x-pirate-actor, x-pirate-nonce, x-pirate-issued-at, x-pirate-deadline and x-pirate-signature. Issue time may be no more than 300 seconds old; deadline must be in the future and at most 300 seconds after issue. There is no reusable bearer token.

Initial POST /v1/ceremonies requires the bound controller signature over the complete proposed binding. Later access accepts that controller or its bound installation-request key. Ceremony consent itself still verifies the controller. HTTP authorization is replayable only within its five-minute scope: creation is idempotent, mutation uses a durable revision fence, and observations reserve a durable rate slot. Replaying a request cannot issue or sponsor a transaction, replace authority or create another logical operation. A reused idempotency key with a changed binding is request_conflict.

All public JSON is closed and duplicate-key rejecting. The body cap is 16384 bytes including streamed input. Exact typed errors are declared in src/outcomes.ts. Operation state and observation schemas are in src/ceremony.ts and src/observation.ts. The HTTP result is pre-submission status only. The Wizard NamespaceControlPort proof reference remains the future interface in the reviewed wire proposal; no fake evidence is exported from this package.
