# Strict song-video master verifier

This is the first, pure-verifier phase of `api-video-cloudconvert-render-integration`.
It makes no provider request and has no R2 or database binding. The caller must
provide the expected 48 kHz sample count and SHA-256 of interleaved signed
16-bit stereo PCM for the selected source-song excerpt. Those facts must be
derived independently of the provider output.

The verifier limits the master to 24 MiB and 3–15 seconds, checks the admitted
MP4 box and sample-table shape before extraction, requires one H.264 track and
one 48 kHz stereo FLAC track with matching zero-based timing, decodes every
FLAC packet and compares the exact PCM digest. It does not establish video-frame
identity. The provider remains trusted for video content until the separately
required frame-comparison gate is implemented before ordinary-user access.

The two fixed masters were generated by the synthetic CloudConvert trial in
`archive/video-cloudconvert-song-master-trial-2026-09-26/`. Their byte digests
and expected PCM digests are pinned in the tests. Neither fixture contains user
media. The decoder is `@wasm-audio-decoders/flac` 0.2.11; its 54,713-byte WASM
module was captured from that exact package by the archived Worker spike. The
vendored module SHA-256 is
`79af31833dba4adae91c7b445b2eaad7d0ba51518356966e2cf37f92610488ed`.
The package's own source is MIT; the compiled libFLAC component has the Xiph
license. Review distribution notices before merging this branch. Upstream
references are https://github.com/eshaz/wasm-audio-decoders and
https://github.com/xiph/flac/blob/master/COPYING.Xiph.

MP4Box 2.4.1 logs a `dfLa` over-read warning on both valid fixtures because its
parser loops again when the FLAC metadata block's last-block bit is set. The
verifier checks that box's actual 50-byte envelope and metadata header before
MP4Box runs. The warning is a parser defect, not permission to accept a
malformed FLAC configuration.

An ephemeral local Worker probe used the exported verifier with no R2,
database, or provider bindings. With
Wrangler's local workerd at compatibility date 2026-08-18, both fixtures passed
and a wrong expected digest returned HTTP 422. Observed request wall times were
263 ms cold for the short fixture and 46 ms for the 15-second fixture. These
are local observations, not billed CPU or a production memory measurement.
