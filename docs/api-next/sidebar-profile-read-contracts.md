# Sidebar and public profile reads

The workspace_owner requested these reads on 2026-10-05 to complete the Solid sidebar and public profile. Video engagement and per-video canonical routing remain separate work. This slice adds no writes or new permissions.

`GET /public/communities/popular` returns at most 100 active communities, defaulting to 20. It ranks by memberships whose status is member, using the same count definition as community previews. Community ID breaks ties. Followers and clicks do not affect the rank. The server supplies the resource destination. Solid merges existing memberships ahead of this list and deduplicates by community ID. Responses are uncached so hidden communities disappear on a fresh read.

`GET /users/me/moderation-communities` uses the authenticated account subject. An entry requires an active role assignment and the existing moderation.view capability on an active community. Creation and membership do not substitute for permission. Current capability policy admits active owners; this read does not broaden it. Pages contain at most 100 entries, ordered by community ID. A cursor belongs to an entry the account can still moderate. Responses are private and uncached.

`GET /public/personas/:personaId/activity` accepts Overview, Posts or Comments as a surface and returns at most 20 entries with a scoped progress cursor. It resolves an active persona on an active account and selects published text/song activity in active communities. Rating and membership checks apply to the viewer resolved by the session boundary. No account ID is accepted from the browser. Only posts attached to the viewed public persona qualify, and the existing content projection checks public authorship again before returning an item. The schema has no invented identity-mode database column. Video posts remain outside this initial canonical-page slice.

Comments must be published and rating-readable, including every ancestor up to a visible root. Orphaned or cyclic chains do not qualify. Hidden, removed and inaccessible ancestor bodies never become profile activity. Post destinations come only from allocated aliases; absent aliases remain unlinked. Public persona projections supply display identity, and no private account or role record is returned.

Activity sorts by exact database creation time, activity ID and kind, descending. Cursors retain microseconds and bind persona and surface; malformed dates and cross-profile or cross-tab reuse fail before querying. A disappeared post still advances the cursor, allowing the browser to continue through a sparse page without looping. The content projection is reused rather than reproduced. Responses are private and uncached, including anonymous reads. Solid must fetch activity in the browser so viewer-specific content never enters the publicly cached profile document.

No follower or contribution statistics, invented comments, comment voting, unsupported overflow actions, created-community profile list, video routes, backfill, production release or Rewards activation is part of this slice. Final API, Solid, PostgreSQL and staging evidence is recorded in the workspace task register.
