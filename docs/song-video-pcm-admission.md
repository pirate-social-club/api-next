# Automatic song timing and PCM admission

This slice starts disabled. Staging declares `SONG_VIDEO_PCM_ADMISSION_ENABLED=false` in the jobs and media Workers; the database policy also starts false. There is no production switch or credential change. Activation and the real new-song proof require their own reviewed staging rollout.

An enabled publication trigger records pending timing and a PCM admission for a public song revision in the same publication transaction. Existing matching PCM references skip generation. The readiness gate remains closed while the reference is absent. One decoder output provides both the exact sample count and PCM identity. The final transaction checks the current public source revision and worker lease, writes ready timing and the PCM reference, then admits the attempt. Deferred constraints enforce matching facts; the state transition checks the database clock against the immutable provider deadline.

The source is at most 64 MiB and its existing probe must report at most four minutes. A fifteen-minute capability grants only its exact immutable MP3 object and current revision. CloudConvert receives no storage credential. The pinned FFmpeg command decodes signed sixteen-bit stereo PCM at 48 kHz. Its output fence is four bytes above the admission maximum, so an oversized song cannot be admitted as a truncated four-minute song.

The transfer accepts only an aligned declared length up to 46,080,000 bytes. A fixed-length stream writes R2 while a streaming digest hashes the same backpressure path. Full readback checks the version, etag, metadata and hash. Recovery after an uncertain database acknowledgement streams an existing version-bound object before trying to obtain another provider export. Neither path buffers the whole song. Transfer and recovery include stalled-read deadlines.

A durable create intent precedes the sole provider POST. Exact-tag lookup adopts a processing job after a lost response, while an empty lookup remains uncertain. Two unresolved intents occupy the capacity bound. Claims are fenced and expire after five minutes; provider waits expire after thirty minutes. Terminal cleanup revokes source authority, removes all exact-tag or recorded jobs, and removes failed PCM output. Admitted output remains. Cleanup must observe a durable terminal state before deleting an object. An uncertain empty lookup retains reconciliation and capacity.

The source gateway queries the new grant and admission tables, so migration 233 and runtime privileges must be verified before deploying this gateway. Deploy the accepted jobs, media and source code with both admission switches disabled. Verify the scoped CloudConvert secret in the media Worker and live gateway and storage bindings. Review the activation sequence before enabling the database policy and both Worker switches. Do not apply this sequence to production or retire the workstation renderer as part of this slice.

The release receipt still requires a newly uploaded staging song, automatic timing and PCM admission, a video-ready readback, a CloudConvert video master and Home playback. Record the real export host, provider time and credits and Worker resource observations. Alert delivery, reconciliation operations and rollback handling must be reconciled with the parent production release gates. Local test results alone do not establish this live journey.

The shared provider parser admits only storage.cloudconvert.com and us-east.storage.cloudconvert.com for PCM exports, preserving URL and redirect restrictions. The consumer calls its fetch dependency unbound, and media composition supplies a wrapper. An isolated workerd regression passes the real global fetch through the consumer with runtime-level outbound interception and real R2 storage: it fails before the repair and passes after, including streamed readback, measured admission facts and cleanup. Observation failures log a fixed phase and allowlisted error class, plus numeric HTTP status when available; exception messages and signed URLs are excluded.

After migration 233, any retained workstation timing role needs SELECT on media_song_video_pcm_admissions so the invoker guard can distinguish unmanaged timing from automatic admission. It must have no INSERT, UPDATE, DELETE or TRUNCATE privilege on that table. The restricted host regression exercises unmanaged measurement and asserts this read-only boundary. This requirement does not authorize restarting the stopped workstation services or changing their live grants.
